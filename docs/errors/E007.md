# E007: attempt to index a nil value

## What it means

The program used `.` or `[]` on a value that turned out to be `nil`.
Under CLua's closed-world compile a missing name resolves to `nil` at
compile time and this becomes a run-time error only when the code path
actually reaches the indexing operation.

## Common causes

- Reading a field from a table that was never assigned
  (`local cfg; print(cfg.name)`)
- Chained field access where an intermediate value is nil
  (`response.body.data.items` and `body` is nil)
- Forgetting to `require` a module and dereferencing it
- A typo in the module or table name

## Fix

```lua
-- Wrong: cfg is nil
local cfg
print(cfg.name)

-- Right: create the table first
local cfg = { name = "default" }
print(cfg.name)
```

```lua
-- Wrong: dereferencing a missing intermediate
local name = response.body.data.name

-- Right: guard with `and`
local name = response
         and response.body
         and response.body.data
         and response.body.data.name
```
