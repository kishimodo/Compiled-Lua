# W004: dead code after `return`

## What it means

Statements were written after a `return` (or `break`, or `error`) in a
block where they can never execute. Compile succeeds -- W004 is
advisory. The critical false-positive to guard against is misreporting
the RETURNED VALUE itself as dead code; the scanner explicitly whitelists
that case (see `tools/test-diagnostics.lua`).

## Common causes

- Extra debug print after an early return that was left behind
- A `return` moved earlier during a refactor without deleting the tail
- A conditional simplified to an unconditional return

## Fix

```lua
-- Wrong: statement after return never runs
local function f(x)
  if x then
    return "hit"
  end
  return "miss"
  print("this line never runs")   -- W004
end

-- Right: delete or move the tail
local function f(x)
  if x then
    return "hit"
  end
  return "miss"
end
```

## Suppression

Silence with `-Wno-dead-code`, or the whole warning set with `-w`.
