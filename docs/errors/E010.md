# E010: dynamic require in a closed-world program

## What it means

The compiler saw a `require(variable)` call whose argument is not a
string literal. In a closed-world AOT compile every reachable module
must be known at build time so it can be linked in; a dynamic require
cannot be resolved and the run-time helper has no way to load a
missing module.

## Common causes

- Computing a module name at run time
  (`local mod = require(kind .. "_backend")`)
- A shim that loops over a list of optional modules
- A test harness that reaches for modules by variable

## Fix

Enumerate the candidates and let the static walker see each string
literal. Wrap the actual dispatch in an ordinary table.

```lua
-- Wrong: dynamic require
local function load(kind)
  return require(kind .. "_backend")
end

-- Right: enumerate the candidates statically
local backends = {
  sqlite = require "sqlite_backend",
  redis  = require "redis_backend",
  memory = require "memory_backend",
}
local function load(kind)
  return backends[kind]
end
```

If the dynamic form is unavoidable (a plugin discovery loop, for
example) force-bundle each candidate with `-L`:

```sh
clua build main.lua -L sqlite_backend -L redis_backend
```
